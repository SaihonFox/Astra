# Astra Agent — Final Product Specification

**Версия:** 1.0  
**Дата утверждения:** 18 ноября 2026 года  
**Статус:** Утверждена владельцем

## 1. Концепция продукта

Astra Agent — персональный автономный локальный ИИ-агент, работающий преимущественно на компьютере пользователя. Он понимает задачи, рассуждает, планирует, принимает решения в рамках разрешений, взаимодействует с ОС, исследует информацию, программирует, обучается и выполняет продолжительные задачи.

Принципы:
- Local-first / offline-first.
- Один единый ИИ-агент.
- Несколько сменных локальных моделей.
- Единая долговременная память.
- Максимальная автономность в рамках разрешений.
- Постоянная фоновая работа.
- Контролируемое самоулучшение.
- Безопасное взаимодействие с ОС.
- Полный жизненный цикл разработки ПО.
- Прозрачность действий.
- Расширяемость без изменения ядра.

## 2. Платформы и оборудование

### 2.1 Платформы
- **Windows:** основная платформа и основной runtime.
- **Linux:** полноценная поддержка.
- **Android:** удалённый клиент.
- Desktop: Avalonia UI.
- Android: Kotlin, Jetpack Compose, Material 3.

### 2.2 Исходное оборудование
Основной компьютер: 16 GB DDR4 RAM, NVIDIA GTX 1650 4 GB VRAM, Intel UHD Graphics, SSD, Windows.
Дополнительный VPS: Ubuntu 26, 4 CPU, 8 GB RAM, 80 GB NVMe. VPS не обязателен и не является обязательным inference-сервером.

### 2.3 Управление ресурсами
CPU inference, GPU offload, динамическая загрузка/выгрузка моделей, ограничение контекста, контроль RAM/VRAM/disk, очередь задач, пауза/возобновление фоновых операций.

## 3. Архитектура единого ИИ

### 3.1 Единый агент
Astra — один самостоятельный агент с единым состоянием, контекстом, памятью, планированием и исполнением. В продукте запрещены независимые ИИ-агенты, делегирование задач сторонним ИИ и облачные AI API.

Специализированные роли могут быть внутренними режимами работы одного Astra, но не независимыми агентами.

### 3.2 Локальные модели
Категории: General, Reasoning, Coding, Fast, Vision, Embedding, Reranker.

Model Orchestrator выбирает модель по типу/сложности задачи, качеству, скорости, контексту, RAM/VRAM, нагрузке и истории успешности. Поддерживаются ручной и автоматический режимы.

Предпочтительна последовательная работа; тяжёлые модели не должны без необходимости загружаться одновременно.

### 3.3 Model Registry
Хранить ID, название, путь, формат, квантование, размер, контекст, capabilities, источник, лицензию, требования к RAM/VRAM, результаты тестов, доступность, preferred tasks и версию.

Основной runtime — llama.cpp; основной формат — GGUF. Архитектура допускает другие локальные runtime.

## 4. Agent Core

Компоненты: Request Analyzer, Intent Classifier, Context Manager, Model Orchestrator, Task Planner, Task Executor, Tool Dispatcher, Result Validator, Response Generator, Session Manager, Task State Engine, Policy Engine.

Жизненный цикл: запрос/событие → анализ → контекст → выбор модели → план → выполнение → проверка → исправление → итоговая проверка → ответ → сохранение полезного.

Task State Engine сохраняет задачи, подзадачи, зависимости, статусы, результаты, инструменты, изменённые файлы, ошибки, решения и checkpoints. Поддерживаются отмена, пауза, возобновление и восстановление после перезапуска. Действуют лимиты времени, итераций, tool calls и токенов.

Режимы Chat, Assist, Copilot, Autonomous, Research, Developer, System — это политики одного агента, не отдельные модели или агенты.

## 5. Автономность и инициативность

Astra работает постоянно в фоне. Источники инициативы:
- события ОС, изменения файлов и проектов, ошибки, обновления;
- расписание;
- самостоятельно сформированные цели.

Astra может создавать задачи, формировать очередь, определять приоритеты, исследовать проблемы, проверять компоненты и улучшать Skills.

Компоненты: Background Host, Event Watcher, Autonomous Scheduler, Goal Manager, Resource Governor, Idle Task Manager, Notification Engine.

Host остаётся активным, но LLM загружается по необходимости.

## 6. Общение с пользователем

Astra сообщает о событиях, предупреждает о проблемах, предлагает задачи и улучшения, задаёт вопросы и сообщает результаты. Безопасные обратимые решения принимает самостоятельно; важные архитектурные и опасные решения согласовывает.

Журнал показывает этапы, инструменты, результаты и ошибки. Частота и приоритет уведомлений настраиваются.

## 7. Memory System

Память независима от модели и сохраняется между сессиями.

Уровни:
- Working Memory — текущая сессия и активные задачи.
- Long-Term Memory — предпочтения, факты, опыт, решения, цели.
- Project Memory — требования, архитектура, файлы, задачи и история проектов.
- Knowledge Base — документация, исследования и проверенные знания.

Технологии: SQLite, FTS5, векторный поиск, embeddings, индексация документов и семантический поиск. Конкретная vector library выбирается после проверки.

Система обнаруживает устаревшие сведения, дубликаты, противоречия и недостоверные данные. Сохраняет источники, confidence, актуальность и историю. Пользователь может просматривать, редактировать, архивировать и удалять данные.

## 8. Learning & Self-Improvement

Три направления:
1. Knowledge Learning — исследование, сбор, проверка и сохранение знаний.
2. Skill Improvement — анализ ошибок, создание и тестирование Skills, версии, применение проверенных некритичных изменений, rollback.
3. Model Learning — подготовка датасетов, эксперименты LoRA/QLoRA, PyTorch, PEFT, оценка и сравнение.

Рабочая модель не заменяется автоматически. Изменение весов и установка новой рабочей версии требуют оценки качества и одобрения пользователя.

Self-Improvement Engine анализирует повторяющиеся ошибки и недостатки Astra.

## 9. Tools & System Integration

Единый контракт инструмента: Id, Name, Description, RequiredPermission, InputSchema, ExecuteAsync.

Категории: Filesystem, Terminal, System, Network, Git, Code, Applications, Browser, Docker, Deployment.

Windows: PowerShell, файловая система, процессы, службы, приложения, сеть, системная информация и настройки.
Linux: Bash, файловая система, systemd, процессы, пакетные менеджеры, сеть, разрешения и Docker.

Research: Search, Browser, PageReader, ContentExtractor, DownloadManager, SourceManager, ResearchEngine. Playwright для браузерной автоматизации. Внешний контент — недоверенные данные; обязательна защита от Prompt Injection.

## 10. Vision & Documents

Vision: изображения, скриншоты, OCR, схемы, диаграммы, UI elements, extraction. OCR отделён от визуального понимания. Предусмотреть Tesseract и локальные vision-модели.

Документы: PDF, DOCX, XLSX, PPTX, TXT, Markdown, CSV, JSON, XML. Чтение, поиск, анализ, сравнение, суммаризация, извлечение, создание, редактирование и экспорт.

## 11. Development Environment

Типы проектов: Desktop Windows/Linux, Android/iOS, Backend/API, Web, базы данных, CLI, библиотеки/SDK, игры, системные утилиты и автоматизация.

Жизненный цикл: требования → анализ → архитектура → план → разработка → сборка → тестирование → исправления → документация → Git → релиз → развёртывание → мониторинг → сопровождение.

Code Intelligence: Roslyn, Tree-sitter, LSP, ripgrep, Git. Языки: C#, Kotlin, Java, C, C++, Python, JavaScript, TypeScript, SQL, Go, Rust, PHP, Swift, Dart, Visual Basic, Bash, PowerShell, Lua, Ruby, Perl, Assembly, Fortran и другие.

Не создавать собственные компиляторы. Использовать существующие компиляторы, анализаторы и LSP. Большие проекты анализировать через индексацию, поиск символов и граф зависимостей, а не передавать целиком в контекст модели.

Каждый проект получает постоянный Project Workspace: Requirements, Architecture, Tasks, Source Files, Git History, Build Results, Tests, Environment, Deployments, Logs, Decisions. Работа восстанавливается после перезапуска.

## 12. Deployment & Operations

Среды: Windows, Linux, Docker, Docker Compose, VPS, выделенные серверы, облачные платформы, NAS, LAN.

Development и Staging могут развёртываться автоматически в пределах разрешений. Production требует проверки конфигурации, резервной копии, одобрения, health checks и безопасного rollback.

Astra мониторит доступность, логи, ошибки, производительность, сертификаты и зависимости. Безопасные проблемы может исправлять самостоятельно.

## 13. Plugins & Skills

Plugins добавляют инструменты, интеграции, форматы, источники данных и автоматизацию. Внутренние расширения используют .NET API; внешние работают в отдельных процессах через версионируемый JSON-RPC.

Skill — инструкции, знания и последовательности действий для использования существующих возможностей Astra. Поддерживаются создание, редактирование, импорт, установка, обновление, отключение, удаление, версионирование и тестирование.

Каталог расширений проверяет источник, подпись (если доступна), лицензию, совместимость, версию, безопасность и разрешения.

## 14. Desktop & Android

Desktop: Avalonia UI, C#, MVVM. Разделы: Chat, Tasks, Projects, Memory, Models, Tools, Knowledge, Learning, Extensions, Settings, System Monitor. Показывать модель, режим, активную задачу, шаги, инструменты, разрешения, RAM/VRAM и результаты.

Android: Kotlin, Jetpack Compose, Material 3. Chat, Tasks, Notifications, Approvals, Projects, Results, Settings, System Status.

Голос — необязательный модуль: распознавание речи, озвучивание и голосовое управление.

## 15. API & Communication

ASP.NET Core REST API и WebSocket/SSE. Предусмотреть `/api/chat`, `/api/sessions`, `/api/tasks`, `/api/models`, `/api/memory`, `/api/projects`, `/api/tools`, `/api/extensions`, `/api/skills`, `/api/learning`, `/api/system`, `/api/settings`.

События: EventId, TaskId, Timestamp, EventType, Payload, SchemaVersion. Контракты версионируются.

API доступен локально и в LAN с аутентификацией и авторизацией. Публичный интернет-доступ не предусматривается. Дополнительно — CLI и интеграции с редакторами кода.

## 16. Security Architecture

Уровни:
- L0 — чтение.
- L1 — временные разрешения.
- L2 — изменение файлов и проектов.
- L3 — системные изменения и установка ПО.
- L4 — критические операции.

Для каждого уровня настраивается автоматическое разрешение, подтверждение или запрет.

Изоляция: отдельные процессы, sandbox, CPU/RAM/time/disk limits, контроль сети, защита секретов, минимальные привилегии. Docker сам по себе не является достаточной границей безопасности.

Критическое удаление, административные операции, Production deployment, изменение политик безопасности, ядра и permission system требуют подтверждения. Все действия журналируются.

Внешние сайты, документы, письма, репозитории и файлы не могут менять инструкции или полномочия Astra.

## 17. Storage & Backup

Раздельные области: Configuration, Database, Models, Knowledge, Projects, Extensions, Logs, Cache, Backups.

Секреты: Windows Credential Manager/DPAPI и подходящие Linux secret stores. Чувствительные данные и резервные копии шифруются.

Резервирование: периодическое, перед важными изменениями, ручное. Хранилища: локальный диск, внешний накопитель, NAS, другой компьютер в LAN, отдельно настроенное пользователем удалённое хранилище.

Поддержать проверку целостности, полное/частичное восстановление и миграции данных.

## 18. Resource Management

Профили: Performance, Balanced, Economy, Background. Возможен ручной и автоматический выбор.

При перегрузке: приостанавливать фоновые задачи, уменьшать контекст, выбирать лёгкую модель, переключаться на CPU, сохранять состояние и возобновлять после освобождения ресурсов.

Hardware & Environment Profiler определяет CPU, GPU, RAM, VRAM, диски, SDK, компиляторы, приложения и доступные инструменты.

- Modular Monolith.
- Avalonia UI.
- Kotlin + Jetpack Compose.
- ASP.NET Core.
- llama.cpp / GGUF.
- SQLite / FTS5.
- sqlite-vec или проверенная альтернатива.
- Roslyn, Tree-sitter, LSP, ripgrep.
- Playwright.
- Tesseract.
- Serilog.
- xUnit.

## 20. Process Architecture

- `Astra.Host` — ядро, Agent Core, задачи, память, планирование, API.
- `Astra.ModelHost` — модели и inference.
- `Astra.Sandbox` — изолированное выполнение.
- `Astra.ExtensionHost` — внешние расширения.

Host постоянно активен. Остальные процессы запускаются по необходимости.

## 25. Ограничения и принципы

1. Один самостоятельный ИИ-агент.
2. Только локальные ИИ-модели.
3. Никаких облачных AI API и сторонних ИИ в runtime.
4. Интернет для исследований, документации, программных компонентов и обновлений.
5. Доступ к Astra только локально и внутри LAN.
6. Ядро и безопасность нельзя менять без одобрения.
7. Критические действия требуют подтверждения.
8. Пользователь контролирует данные.
9. Память независима от модели.
10. Автономные действия журналируются.
11. Результаты проверяются.
12. Автономность учитывает ресурсы оборудования.

**Цель:** создать самостоятельного локального цифрового помощника, который непрерывно работает, развивается, исследует информацию, управляет компьютером, разрабатывает ПО и выполняет сложные задачи, сохраняя единый интеллект, память и контроль пользователя над критическими действиями.
