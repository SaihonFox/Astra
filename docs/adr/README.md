# Architecture Decision Records

Create one Markdown file per significant decision, using sequential identifiers such as `0001-modular-monolith.md`.

An ADR should contain:
- Status: Proposed / Accepted / Superseded.
- Context.
- Decision.
- Alternatives considered.
- Consequences.
- Security implications.
- Validation plan.

Do not silently reverse an accepted decision. Create a superseding ADR and obtain owner approval for changes that affect the product specification.
